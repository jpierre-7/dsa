# Mission: Data Structures & Algorithms

## Why
Close the CS-fundamentals gap left by learning to code without a degree, so I can (1) pass LeetCode-style technical interviews and (2) pick the right data structure and spot slow code in my day-to-day Python work.

## Success looks like
- Glance at a Python function and state its Big-O time and space, with a reason
- Choose between list, set, dict, deque, and heap for a job and explain the trade-off
- Recognise and apply each core pattern: **two pointers, sliding window, fast & slow pointers, binary search (and its variations), DFS & BFS, dynamic programming, and backtracking**
- Solve LeetCode "Easy" problems without help, and most "Medium" problems in those patterns in about 30–40 minutes
- Talk through my approach out loud the way interviewers expect
- Find and fix at least one real performance problem in my own code using this material

## Constraints
- Casual pace, irregular sessions, so each lesson has to be finishable in one short sitting
- Python only
- Already a comfortable programmer, so skip syntax and basic control flow
- Learns by doing: never hand over answers; make the user work it out, then check their understanding

## Out of scope
- Formal proofs, and amortized/probabilistic analysis beyond intuition
- Competitive-programming-only topics (segment trees, advanced number theory, heavy combinatorics)
- System design interviews
